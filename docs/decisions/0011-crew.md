# 0011: Crew: up to three personas, one speaker at a time, session file from the launcher

Date: 2026-11-17
Status: Accepted

## Context

Personas now have roles per game (Elite: Mira the ship's AI, Frieren the copilot, Megumin a
stowaway), but only one can run. The Commander wants a crew of up to three that speak at different
moments, banter in quiet stretches and share memory. One crew member per game carries out hands
actions. Before Start, the GUI picks game, crew, language, action-carrier and a banter level; the
voice process reads the resulting settings file. Nothing is hardcoded. The LLM is flash-lite on a
free quota, so call count matters.

## Options

1. Calls: one call per spoken line everywhere; one narrator call for everything; hybrid (one
   persona per player reply, one call per banter scene).
2. Other speakers in history: labelled `model` turns; labelled `user` turns; a transcript preface.
3. Addressing: exact aliases vs fuzzy matching of names in speech-to-text.
4. A non-carrier asked to act: delegate to the carrier vs refuse in character.
5. Launch settings in `config.toml` vs a separate session file.

## Decision

- **Hybrid calls.** A player turn is answered by one persona in one call, with tools as today. A
  banter scene is one tool-free call returning 2-4 lines tagged by speaker id, validated (known
  ids, no player lines) and split into separate playback items; a malformed scene is dropped. A
  crew of one uses the same code path.
- **One speaker at a time.** One playback queue; each item carries its speaker's voice (and later
  an optional stereo position, off by default). Push-to-talk drops the whole queue, including the
  rest of a scene; a critical alert cancels a scene.
- **History is structured** (`speaker_id`, kind, text, heard/interrupted, tool links), never
  name-prefixed text. A renderer turns it into each persona's prompt: her own past lines as
  model turns, other crew lines in a labelled transcript preface, the player as user. The renderer
  is swappable and is checked live with flash-lite. A leading `Name:` is stripped before storage
  and speech. Other crew see tool outcomes, not raw payloads. Only heard text counts as said.
- **Who speaks.** Exactly one responder per turn. Order: an alias of a crew member at a word
  boundary (aliases per language in the persona YAML, including the user's own mishearings; no
  automatic fuzzy matching; first hit wins); else the last speaker while the follow-up window is
  open; else interest weights for the topic; ties go to the carrier, then roster order. Events
  use per-persona interest weights per event kind; critical alerts go to the carrier.
- **Hands.** Mutating actions are offered only on the carrier's calls; read-only query actions
  (e.g. Elite `nearby_systems`) may be offered to anyone through a `read_only` flag on
  `ActionSpec`. Asked to act, a non-carrier answers in character and names the carrier; nothing
  is silently rerouted. Banter calls get no tools; a pending confirmation suppresses banter.
- **Banter budget.** Banter replaces idle chatter, never stacks on it. The slider (0 = off) maps
  to a minimum quiet gap and a maximum of scenes per hour (tuning constants in core, scaled by
  persona chattiness); default low. Banter is dropped first when the LLM quota is near its limit
  or a model is parked.
- **Session file.** `~/.config/familiar/session.toml`, versioned schema: game, crew ids (1-3,
  unique), language, carrier (a crew member), banter level. Written atomically by the GUI,
  validated by the voice process at Start (fail closed: unknown keys, missing persona, a member
  without a voice for the language). Precedence: CLI/env > session > `config.toml` defaults;
  it never holds secrets or devices. No hot reload; it doubles as the remembered last selection.
- **Memory.** Rows record the source speaker; facts the player observed are kept apart from
  persona claims, so playful fiction never becomes fact. The recall cooldown is crew-wide.
- **Phases.** 1: session file, launcher crew screen, speaker selection, per-speaker voices,
  structured history, carrier-only actions, memory attribution. 2: banter scenes and budget.
  3: stereo placement, memory callbacks, Touch Portal.

## Consequences

One persona stays a crew of one, so existing setups keep working once migrated to the session
file. Persona YAML gains optional `aliases` and `interests`; relationships stay in the user's own
persona files. Banter costs one LLM call per scene plus TTS characters per line. Impersonation
can only be reduced by prompting and validation, never ruled out.

## Who agreed

- codex: hybrid; structured transcript, crew lines as labelled model turns; one owner per turn,
  conservative fuzzy names; slider maps to quiet gap and hourly cap, banter off or low by default;
  versioned session schema with atomic writes and fail-closed validation; carrier-only tools with
  delegation; heard vs generated text; player observations vs persona claims.
- agy: hybrid; name prefixes stripped before TTS; fuzzy aliases; follow-up stickiness; interval-
  based slider; session file separate from config; carrier-only tools, non-carrier refuses in
  character; speaker id on memory rows; barge-in purges the scene.
- grok-4.7 (Copilot): hybrid, crew of one on the same path; no other speakers in model or user
  roles, a transcript preface instead; word-boundary aliases, no fuzzy; ties to the carrier;
  critical alerts cancel scenes; banter replaces idle chatter; precedence CLI > session > config,
  no secrets; mutating tools only for the carrier, read-only for all; refuse in character.
- Claude (coordinator): merged; history renderer made swappable with grok's layout as default
  pending a live check; non-carrier refusal by majority; fuzzy matching replaced by user-editable
  alias lists.
- Commander: up to three crew, one action-carrier per game chosen in the launcher, banter slider,
  every launch choice in the GUI and a settings file read at Start.
